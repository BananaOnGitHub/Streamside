# Built-in investigations

The initial RN chat profile selects versioned compiled capabilities. Its
event-driven armed lifecycle has no fixed expiration. Capture returns to Armed;
explicit Disarm ends collection. The native parser rejects unknown/duplicate
fields, new hooks or fields, incompatible profiles and limits above compiled
ceilings. Capability availability requires separate native donor, bootstrap and
command-channel admission.

The bundled registry is pinned to its exact original bytes with SHA-256 using
the system cryptographic primitive. An optional cached copy must match that
same pin; malformed or different bytes fall back to the verified bundle. This
is immutable bundled configuration, not a mutable remote update service.
Future fixed-repository retrieval can provide only those pinned bytes. Signed
mutable updates, transport and disk caching are not implemented in this stage.
No downloaded manifest can execute code or transmit diagnostic reports.

Regenerate the checked-in byte array with
`python3 tools/generate_investigation_registry.py`; `--check` detects stale data.
The native parser is the admission authority. The JSON Schema is an authoring
aid; integer spelling, UTF-8 byte budgets and cross-field capability/resource
checks are additionally enforced by the native parser.

Registry revision 5 selects the implemented translation, emission/local-echo,
aggregate store, IRC reward, reward-store and list-lifecycle adapters. Revision 1
is preserved as an earlier schema fixture, not an accepted cached replacement.
Filtering/deduplication, confirmed reconciliation, renderer/catalog and native
row/Fabric geometry are reported unavailable. Snapshot profile rn-chat-current-v4
samples the admitted unbuffered viewport first, two-row margins second and the
bounded newest-first store tail last. numeric-chat-v4 adds frozen ring-overwrite
and saturation data; unknown membership and measured-zero/cache-missing states
remain distinct. The observer never infers server receipt.

Every ordinary build checks the committed, fingerprinted compiled-Hermes
validation receipt in `diagnostics/validation/hermes-v1.json`. A clean build
does not need copyrighted donor contents; replaying or refreshing that proof
requires the exact donor and the pinned Hermes toolchain. Run
`make test-investigation-runtime` with the same input variables as
`make test-rn-virtualization`. Changed runtime/graft/fixture inputs invalidate
the recorded proof and stop the build. This receipt records host validation,
not independent CI replay or device acceptance.

## Runtime controls and configuration authoring

Arm/Capture/Stop operate immediately on compiled, admitted capabilities without
changing general logging presets or reopening chat. Those controls are separate
from changing the bundled configuration. Regenerating the registry into a binary
is a normal reviewed source/build change; it is not a remote update.

The authoring schema is version 1. Current snapshot/report profiles are
rn-chat-current-v4 / numeric-chat-v4; runtime ABI1 and each compiled capability's
version remain explicit. Use a new immutable manifest revision when reviewed
parameters change. Limits may only narrow the compiled ceilings, and selection
must also satisfy operational constraints. Existing event-family names can
select only available compiled adapters. New observation fields, hook targets,
semantic capability versions, donors or output profiles require compiled code.
A valid signature in the future cannot supply those missing implementations.

## Required v2 update capability — design only

Secure, GitHub-hosted, remotely updateable configurations remain required future
work. See the [implementation-oriented v2 plan](../docs/investigations/SECURE_INVESTIGATION_UPDATES_V2_PLAN.md)
for trust boundaries, exact signed-byte rules, TUF/Ed25519 roles and rotation,
GitHub publication, persistent anti-rollback state, metadata formats, state
machine, threat cases and finite M0–M6 gates.

The proposed transport uses a compiled fixed repository and raw GitHub host;
signed metadata authorizes exact target hashes and full target commit IDs.
One explicit bounded refresh, no redirects, native strict admission and atomic
verified caching preserve the offline bundle. Cache and security-head commits
are separate so crashes cannot erase rollback protection. The design defines
expiry/revocation/offline recovery and immutable active leases. No downloader,
public-key bootstrap, mutable configuration admission or disk cache currently
implements it. Fetching the currently pinned bytes would not satisfy v2.

During v1 hardening only a read-only copied configuration identity and
capture-pinned provenance were added to preserve the separation of consumers
from trust admission. No remote setter, test-key bypass or alternate trust path
was introduced. V1 completion is not completion of the required v2 architecture.
