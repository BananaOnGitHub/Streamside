# Native frontend candidate — device test

The first signed-in reports passed runtime/report consistency checks, and signed-out launch, background/return and full restart have now been confirmed with zero monitored runtime counts in the supplied reports. See the [signed-in review](NATIVE_FRONTEND_PHASE2_DEVICE_REVIEW_1.md) and [signed-out review](NATIVE_FRONTEND_PHASE2_DEVICE_REVIEW_2.md). Both IPAs need your usual sideload signing step. Keep the same app identifier, signing profile and keychain access used for your current Streamside/Twitch installation. **Install over the existing app; do not uninstall it.** A different signing identity can prevent account restoration and invalidate this test.

1. **Install the baseline IPA.** Choose `StreamsideNativeProof-Twitch32-baseline.ipa` in your existing sideload tool. Open Twitch, confirm your existing account and visit Home/Browse briefly. Do not start a stream for this test. The baseline deliberately runs Twitch's original frontend.
2. **Open Diagnostics.** Hold two fingers still on the Twitch screen for one second. The revised baseline has no floating button, so Settings and sign-out remain reachable. Use Return to Twitch to dismiss Diagnostics. Wait for “Baseline positive control observed.” If it stays incomplete, return to Twitch and exercise its normal browsing screens, then check again. An incomplete baseline is a result to report; its missing counters do not prove zero activity. Wait about 30 seconds in the foreground and use **Export report**, saving the files to Files. Baseline exports contain only `baseline-latest.json` and, when available, `baseline-previous.json`.
3. **Install the native IPA over it.** Choose `StreamsideNativeProof-Twitch32-native.ipa` using the same signing settings. Open it. You should see a simple native diagnostic list. Check that the displayed account is yours and that followed channels match real follows. Only the first 50 are requested. “Live status unavailable” is expected for this query.
4. **Refresh and reopen.** Tap Refresh twice. Return to the phone's Home Screen for about 10 seconds, reopen the app, and check the account/list again. Wait about 30 seconds in the foreground, then export. Record whether the account, list and all zero runtime-entry counts are correct. Any failure or unverified status counts as incomplete.
5. **Test a full app restart.** Close the app from the app switcher, open it again, and confirm the same account and real follows return. Wait about 30 seconds and export again. Native exports contain only `native-latest.json` and, when available, `native-previous.json`. Keep them together with the separately saved baseline report. The previous file preserves the earlier process's counters.
6. **Return the reports and observations.** Include whether the native interface opened, account restoration worked, real follows appeared, refresh worked, transitions/reopening worked, and any failure text. Reports contain numeric diagnostics, source/build identities and memory/timing observations; they exclude account names, channel names, credentials and chat content. Screenshots are optional and may contain your account/channel names.

If the native app closes, stop repeating the failing action and retain the iOS crash report. If the native build can reopen safely, export its latest and previous reports. Reports remain saved across over-installation, but the baseline export does not include native reports. If the native build cannot reach Export, its saved report is not accessible through this interface; preserve the crash evidence and report that limitation. If neither build opens, retain the installation error or iOS crash report. That is a failed/incomplete test, not a passing zero-runtime result.

Use the latest matching baseline/native pair together: its proof identity differs from the original pair, so export a fresh baseline before testing the revised native build. Keep the original reports.

For a signed-out test, first preserve the authenticated reports. Use Twitch's normal sign-out in the baseline, install the native candidate over it, and check that it shows no authorized session and no stale account/follow list. Return to Twitch's normal sign-in flow when needed. The candidate has no independent login screen. Invalid/expired-session and account-switching cases still need a suitable real session and separate observations; do not export or alter credentials to manufacture them.

Memory comparisons need the same device, OS, signing settings and approximately the same foreground wait. Export after leaving Diagnostics visible in both builds. The recorded startup interval begins inside the diagnostic initializer; full cold-launch profiling still needs an external measurement or Instruments. See [the technical report](NATIVE_FRONTEND_TWITCH_32_PHASE2.md) for validation limits.
