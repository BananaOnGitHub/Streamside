# Workspace cleanup and preserved build history

Later tooling audit: verbatim record copies and raw logs described below now live
in the [published recovery checkpoint](../archive/WORKSPACE_BUILD_RECORDS.md).
Compact identities/results remain here; the original cleanup outcomes are unchanged.

The starting checkout was `6af4e2da268d4506e454b8841ab6b5b11a61c009` on
`feat/native-frontend`. Its ignored `build/` directory held approximately 2.2 GiB
of generated outputs and a compiler. The sibling artifacts directory held older
3.1.0 build 19–24 candidates. Cleanup changes output placement, not frontend or
authentication behavior, and does not rebuild the downloaded SwiftUI candidates.

## Preserved evidence

[The original inventory](evidence/workspace-history/before-cleanup.json) records
paths, sizes and SHA-256 for 208 files (2,944,598,489 bytes), including all 15 IPAs.
Compiler installations, caches and large non-IPA objects are excluded from that
inventory. [The record map](evidence/workspace-history/record-map.json) identifies
161 verbatim text records: build logs, failed Apple build attempts, compiler and
artifact manifests, validation receipts, and device instructions. Historical
Markdown is stored with a `.md.txt` suffix to preserve its original relative links
as evidence rather than expose them as current navigation. Original absolute and
relative paths inside receipts remain unchanged. The former workspace note is
also retained as `evidence/workspace-history/WORKSPACE-before-cleanup.md.txt`.

The initial secret-pattern scan of selected text found no private keys, GitHub
credential strings, bearer credentials or OAuth credential strings. No credential
files were inspected or copied. Existing investigation and device records remain
in their original committed locations. The earlier Hermes validation receipt is
preserved in `diagnostics/validation/history/hermes-before-external-artifacts.json`;
the current receipt must be regenerated against the changed build inputs.

## Completed validation and cleanup

The preserved evidence was committed and pushed as
`319a2f61c4ff3861394382fecd665a1382a4facc` before removing superseded binaries.
[The cleanup result](evidence/workspace-history/cleanup-result.json) records exact
removals, retained hashes and the legacy build-24 recovery. The cleanup selection
also removed the intended build-24 rollback IPA; repackaging the original donor
with its preserved native framework restored exactly the original SHA-256
`1d7179fc899c32c297803623a2e1808838e3262c56bded4021e00ec14e87d530`.
The SwiftUI and UIKit pairs were hash-checked after relocation and remain unchanged.
Net removed file contents total 2,116,404,106 bytes (about 1.97 GiB), before newly
created validation outputs/caches and filesystem allocation differences.

[Validation results and generated package hashes](evidence/workspace-history/validation-result.json)
identify the checked outputs. The host suite ran 223 tests: 221 passed and two
Apple-only checks were skipped (Foundation and ImageIO). The 25 native frontend
checks passed. Three new output-placement tests are included in the host total;
they cover defaults, an external path containing spaces, and rejection of checkout
or symlink paths resolving into it. Mandatory pinned Hermes tests passed for both
profiles; the compiled snapshot pipeline accepted 32 bounded snapshots. Native
cross-compilation, artifact verification, two DEB variants and release ZIP
packaging succeeded under the external artifacts directory. Test/build logs are
preserved in `evidence/workspace-history/cleanup-validation/`.

The current Hermes receipt was regenerated by executing the required validation,
not by manually editing fingerprints. The earlier receipt remains archived.
The ordinary build/package smoke checks do not create a new native frontend IPA.
The Apple VM was not needed for this cleanup; its prior build results remain
historical evidence. The first updated CI workflow was rejected before jobs started. Artifact-root
selection was moved into a setup step using the runner environment; subsequent
CI status is recorded separately. The accepted workflow then exposed two host
tests relying on the local compiler fallback because CI only added Zig to PATH.
CI now explicitly exports `ZIG` for those existing compiler-dependent tests.
Physical-device behavior was not revalidated.
